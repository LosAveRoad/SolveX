## Why this is a REVISE verdict, not a reject

The four core deliveries (D1–D4) are conceptually sound and fully implemented; no delivery is missing. The problems are correctness/consistency defects in specific numeric lexicons and two silent artifact regressions, not structural flaws:

1. **D2 "share" units (correctness, high).** `wk["phi_share"] = wk["phi_pmean"]` where `phi_pmean = a_i/A0 * n_w` is the Dirichlet **posterior mean count** (`run_main` line ~710), i.e., in vote units, not unit-summed. Its per-week sums equal n_w (recomputed: min 2.0, mean 8.29, **max 16.0**). It is treated downstream as a probability: clipped only to (1e-4, 1−1e-4) in `fit_fan_gee`, so 747/2777 rows are rendered at 0.9999 in the Binomial log-likelihood (elementwise max = 5.47). `results.json` records `phi_share_sums_to_1_max: 16.0` — the model's own summary literally documents the contradiction. The fitted "D2" coefficients should be read as the weighted empirical mean of φ̂, and D2_age (−0.190, p=1.8e−16) as a weighted-N Binomial mean, not a decoupled fan response. Fix is one assignment line; everything downstream (including the training/test split, the smp-aux spec and the uncertainty weighting) is unaffected because `phi_tilde_hat` and `S_hat` never consume sd-normalized weights.

2. **Statistical coverage mislabels (medium).** A parametric "±1.96 s.e." band appears in the figure legend for F8 when `arch_rows` stores `percentile 10/90` of 400 β-draws (`make_figures.py`, F8 block). This resembles the α=0.10 equal-tailed credible object actually computed (two-sided 90% quantiles, `np.percentile(surv_draws, 10)`, line 1141) and is reported as such in the archetypes summary. Re-label as "90% equal-tailed interval (parametric bootstrap over Cox-β draws)" or regenerate with α=0.05 quantile draws (`np.percentile(surv_draws, [2.5, 97.5])`).

3. **Delta-method GLM gap for bounded shares (low).** The D1 partial R² for the industry block uses a per-column normal/Wald matrix on the dummy set (`wald_partialR2` with `pinv(V)`, line 1027). Covariate support is very heterogeneous (n=93–1247 rows per p_g level, industry levels 61–128 cast-seasons but `ind_Racing_Driver` only 61 cast-weeks); the "chi2/(chi2+n)" differencing rule is fine for the *linear* link, but the D2 fan-channel code path inserts it inside the cluster bootstrap that re-matches dummy columns by name only (`tr_cols` in the validation loop). At LOIO splits with heavy block-diagonal missingness the keep-list variants re-map silently (fix: pass `tol=0.15` to the local `nondegenerate` call so the removed columns are at least reported, not silently re-run).

4. **Season-jackknife CSV silently empty (completeness, medium).** `model3_season_jackknife.csv` is 0 bytes. The internal log confirms the loop ran (`[robustness] season-jackknife (n=0): D1 age-sign flips=0`): the 0-length output means the `try/except` caught an exception in every one of 34 iterations (most likely in `pd.factorize`-grouped MixedLM raise on singleton refit columns) and swallowed it via `except Exception as e: log(...)`. The written log does not confirm that the per-item failure reason was retained inside the same `robustness` JSON section. Fix: change `except Exception as e:` to add `"age_coef_judge": None, "error": str(e)` rows to `sjk`, drop the continue-branch, and re-run — then at least one row per dropped season is written even when a fit fails, and the failure cause is inspectable. Same pattern applies to `model3_loio_robustness.csv` (6 rows, 4 empty columns) — nearly all entries are blanks, so neither robustness table can be consumed from the CSV side.

5. **Stale summary text (completeness, low).** `results_summary.md` duplicates the SolveX artifact-scan prose (references "results.json (13837 B)" while the file is 10501 B, cites a "figures/ F10_partner_effects.png 214794 B" figure identical to F7 in the scan list that does not exist as a duplicate, and states a 131-row "model3_covariate_effects.csv 18910 B" file consistent with the real 162 rows). One regeneration after the fixes above is sufficient; no functional change.

**Bottom line.** The final numerical family (~2777 danced weekly scorecards, 34 seasons, 408 celebrities, 297 elimination events, judges' score trajectory, fan-vote recovery of 83.5% bottom-2 hit-rate over a 59.6% judges-only baseline, age effect on both channels and on the differential, survival/counterfactual layer) is *not* reliable as-is: its succeeded only because consumers read the D2 estimates as generic fan-response output, but the labeling rope is broken and the two robustness tables are dead weights. One D2 rescale, one legend/label correction, and reproducible error handling for the two robustness loops would bring this model to defensible.

## Issues Found:

1. **D2 response in wrong units.** `wk["phi_share"] = wk["phi_pmean"]` (vote-count units; per-week sums 2–16, 747/2777 rows > 1, elem.max 5.47) is passed to `sm.families.Binomial()` as if it were a probability; it is forced to the (1e-4, 0.9999) clip in `fit_fan_gee`. `results.json["phi_share_sums_to_1_max"] = 16.0` documents the contradiction inside the model's own summary. All fan-channel coefficients (D2_age = −0.190, D2_ind_* etc.) currently inherit this distortion.
2. **Stale figure legend.** F8 (`make_figures.py`, archetype block) labels the 10–90 percentile band as "±1.96 s.e. (parametric bootstrap over Cox-β draws)"; the stored values are equal-tailed 90% quantiles of 400 multinomial-normal draws (α=0.10), not ±1.96 s.e. (which would be 95%).
3. **Delta-Wald matrix mixing linear and binomial lexicons.** `wald_partialR2` chi²/(chi²+n) differencing is applied to the dummy set for both the MixedLM (linear link) and the weighted Binomial GEE (logit link); support rates for some cells are decreased further by the per-split `nondegenerate` keep-list variant, which re-maps removed columns silently.

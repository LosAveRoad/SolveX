### 迭代记录（问题 → 证据 → 修复 → 验证）

**r0 → r1**
1. *写隔离从未生效*：3/3 并行实现任务改写了共享 `01_modeling/master_plan.md`，没有一次被拦截。`safetyExtension` 只在单测里被调用过，`PiAgentRunner` 从未把它挂到真实 session 上。另外，模型 3/3 使用绝对路径写文件，旧的「相对前缀 startsWith」比较本身也不成立。
   → 每个 session 都挂载拦截器，前缀和目标路径统一解析成以 cwd 为基准的绝对路径再比较；拦截时返回的 reason 告诉模型允许写的目录。r1 起 3/3 被拦截，Agent 收到原因后转回自己的目录继续工作，有代码的模型从 0/3 升到 3/3。
2. *失败被吞成 completed*：r0 遇到约 50 s 的上游 TLS 中断（`SSL: UNEXPECTED_EOF`，事后 16/16 并发探测全部正常，确认是瞬时故障）。9 个会话的 27 次 SDK 重试全部落在窗口内，重试预算只有 2+4+8≈14 s。失败调用没有抛错，P4 一行论文没写也照样报 completed。
   → 重试预算改为 6 次指数退避（累计约 2 分钟）；重试耗尽仍出错就抛 `AgentRunError`；P4 增加产物门（没有 main.tex 就判失败）。
3. *token 虚高 2.6×*：`collect()` 对 message_start、每个 message_update、message_end、turn_end 都累加了同一条消息的 usage。→ 每条 assistant 消息只在 message_end 计一次。

**r1 → r2**
4. *修复引入的误判*：r1 有 4 个会话被判为 `AgentRunError`，其实是 maxTurns 截断后 abort 留下的空 error 消息，P4 已写出的 18 KB 论文也因此被判失败。→ 区分「轮次上限截断」和「模型故障」，前者返回 `turnCapped` 并告警。
5. *轮次预算是瓶颈*：4/4 长任务（3 个 IMPL + P4）撞上 maxTurns，3/3 IMPL 在耗尽前没来得及写 results_summary.md。→ 剩 3 轮时用 `session.steer()` 插入一条预算提醒，让模型停止探索、先保存交付物。Agent 自写摘要从 0/3 升到 3/3，有图从 1/3 升到 3/3。
6. *token 少报 94%*：Pi 的 `usage.input` 不含命中缓存的部分（r1 缓存占 prompt 的 72%）；失败会话的用量被丢弃；同一任务的多次调用是覆盖写入。→ 计入 cacheRead/cacheWrite，失败调用也计入，按任务累加。r2 起和 gateway 实计**逐 token 一致**。

**r2 → r3**
7. *交叉评审结论全部丢失*：评审是只读工具集，而旧提示词要求它「写入 review 文件」，所以这个文件永远写不出来；解析结论时又只读这个文件和实现者自写的 handoff.json，从来不看评审 Agent 自己的输出。r1+r2 里评审一共给出 3 份 NEEDS_REVISION，编排层接住 0 份，修复 0 次。
   → 结论从评审者的输出里解析；评审全文由编排层落盘；提示词资产逐字保留，只在运行时追加一段「只读、由 SolveX 代存」的说明。r3 里 3/3 结论被接住，触发 3 次定向修复。

**新发现**
